# Proving test AB#99 — only the owner's session can end a trip

Cross-device trip close check for the bug of 2026-11-05: a second device or
another account must not be able to adopt or end someone else's Active trip.

Run against the production backend `https://revolutioninsure-back-end.vercel.app`
on **2026-11-23 05:57 UTC**, after AB#77 (trip ownership), Bug 89 (sign-out
revokes the session) and AB#106 (consent) were merged.

**Result: pass, 15/15. No Bug filed.**

| # | What is checked | Result |
| --- | --- | --- |
| 1 | Another account cannot adopt the Active trip | ✅ 2/2 |
| 2 | Another account cannot end, upload to or read it, and it stays Active | ✅ 5/5 |
| 3 | No token, a made-up token, or a signed-out owner session cannot end it | ✅ 4/4 |
| 4 | Control: the owner's own second device may adopt and end it | ✅ 4/4 |

## What "someone else's" means here

- **Another account** (B) is someone else. B must not get A's trip handed over
  by Start's `active_trip_exists` answer (the 2026-11-05 bug: one Active trip in
  the whole system, adopted by whichever device pressed Start), and must not be
  able to end, upload to or read it.
- **A device without a live owner session** — not signed in, a forged token, or
  a device where the owner signed out — must not be able to end it either.
- **The owner on a second device** (same account, separate session) is not
  someone else. Picking up and ending one's own Active trip from another device
  is how the app recovers a trip after a restart, so it is expected to work and
  is checked as a control. If the team wants even the owner's other devices
  refused, that is a different rule and needs a decision.

## How it was tested

`scripts/prove-trip-end-ownership.mjs` drives the live HTTP API exactly as the
app does — no database keys, no mocks. It creates two fresh accounts, records
their consent, starts a trip for A, then makes every attempt above.

- After groups 2 and 3 it reads A's trip as A and confirms it is still
  **Active**, so "refused" means a trip that was really not ended, not just a
  status code.
- Check 3.3 first shows the fresh session works (A can read the trip), then signs
  it out, so its `401` proves the sign-out revoked it.
- The owner's End (4.3) only has to get past the ownership check (not
  `401`/`404`). Scoring after that is not part of this story, so a scoring
  hiccup would be reported, not counted as an ownership failure. In this run it
  scored normally (`200`).

Passwords and tokens are generated by the script and never printed. Exit codes:
`0` every check passed, `1` a check failed (file a Bug), `2` setup failed
(backend unreachable, sign-up refused) — not a product bug.

```sh
node scripts/prove-trip-end-ownership.mjs https://revolutioninsure-back-end.vercel.app
```

Test data left in production: accounts
`proving-99-a-20261123055722-c148c4@example.com` (one trip, ended and scored)
and `proving-99-b-20261123055722-c148c4@example.com` (one empty trip, ended by
the clean-up step: `HTTP 200`). An earlier run of a first version of the script
(same results, 14/14) left `proving-99-a/b-20261123053413@example.com`.

Related evidence: database-level isolation is proven by
`tests/trip-ownership-rls.sql` (AB#77), and account isolation across reads and
uploads by `scripts/prove-account-isolation.mjs` (AB#78). Check 3.3 also
confirms in production that the Bug 89 fix works.
